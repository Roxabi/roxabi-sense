# Error Handling Audit — P01–P04 (full source)

**Scope:** `src/roxabi_sense/**/*.py`, `tools/**/*.py`  
**Date:** 2026-07-31  
**Axis note:** Failures on focus/Wayland must not block agent-session collection (backend-patterns).

---

### Summary

Error handling is **deliberately fail-open at the sensor layer**: collectors and AT-SPI FFI wrap broadly so one broken source cannot stop the daemon. That design is largely correct for an attention sensor, but several gaps remain:

1. **Store / config decode paths are fail-closed (crash)** — unguarded `json.loads` on event rows and unguarded TOML load can take down every CLI surface with a traceback.
2. **Collector/daemon failures are logged to stdout only** — no meta counters, no `status` visibility when a collector repeatedly errors.
3. **Idle-watch callback swallows exceptions with `pass`** — the only totally silent product-path handler failure.
4. **CLI exit codes are partial** — `day`/`recap`/`mcp`/`atspi-trace` are intentional; `once`/`daemon`/`status` always 0 even when sensors are dead or DB missing.
5. **No bare `except:`** found. Broad `except Exception` is concentrated in AT-SPI worker (justified) and daemon tick isolation (logged).

No P0 (security / data-loss / silent corruption of facts with write-side effect). Highest severity is P1 (ungarded decode → full process crash).

### Recommendations

**Priority order**

1. **Hardening decode (P1)**  
   - Guard `Store._row` JSON decode.  
   - Guard `load_config` with stderr message + exit 2.

2. **Make sensor failures observable without failing closed (P2)**  
   - Log idle-watch callback errors (parity with AT-SPI).  
   - Persist collector / AT-SPI / probe error meta for `sense status`.  
   - Handle AT-SPI `type=error` in `handle_atspi_msg`.

3. **Exit-code / automation contract (P2–P3)**  
   - Document: `status` 0 always when presence shape emitted; `day`/`recap` 1/2; `mcp` 2.  
   - Align `atspi-trace --json` exit with human path.  
   - Optional non-zero `once` only for hard failures (not empty inventory).

4. **Keep intentional fail-open**  
   - Do **not** turn collector `tick_all` into fail-closed — violates “focus failure must not block agent-sessions”.  
   - AT-SPI worker broad catches are acceptable; invest observability on the **host** side instead.

5. **Session registry silence (P2)**  
   - Rate-limited warn on corrupt JSON so operators notice broken `~/.grok` / `~/.claude` inputs without crashing.

**Design stance (sensors)**

| Claim | Policy |
|-------|--------|
| “User is active” with high confidence | **Fail-closed** (presence already does via offline/degraded) |
| “Write a focus fact this tick” | **Fail-open** (skip write) |
| “Daemon stays up if one source dies” | **Fail-open** (isolate + respawn) |
| “Surfaces can read store” | **Fail-closed on integrity** (batch rollback); should **fail-open on corrupt row** (EH-01) |
