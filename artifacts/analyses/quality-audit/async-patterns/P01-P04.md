# Async Patterns / Concurrency & Resources — P01–P04 (full `src/roxabi_sense`)

**Scope:** `src/roxabi_sense/**/*.py`  
**Date:** 2026-07-31  
**Domain:** Async Patterns (concurrency, blocking I/O, resource lifetime)  
**Partitions:** P1 collectors · P2 store/daemon/cli · P3 report/surfaces · P4 atspi/util

### Summary

roxabi-sense is **entirely synchronous**: zero `async def` / `await` / `asyncio` under `src/`. Concurrency is **main-thread daemon + daemon reader threads + long-lived subprocesses**, with SQLite confined to the main thread via `queue.Queue` handoff. That architecture is sound and avoids classic async misuse.

Risks cluster on **subprocess/thread lifecycle**, **unbounded queues under event storms while the main loop blocks on polled collectors**, and **respawn races** (especially `IdleWatch.ready`). Store lifetime is generally correct (`close()` / context managers). No multi-threaded SQLite access is attempted; CLI concurrent opens rely on WAL + `busy_timeout`.

**No P0.** Highest items are incomplete `IdleWatch.stop` (zombie / ready race) and poll-path blocking that delays SIGTERM and starves AT-SPI/idle queues.

### Recommendations

1. **Unify subprocess agent stop** (`IdleWatch` ← `FocusAtspiAgent` pattern): stdin/stdout close, terminate → wait → kill → wait, join reader, generation-safe flags. Highest ROI for AP-01/AP-06.
2. **Bound and coalesce event queues** under the daemon: `maxsize` or drop intermediate focus events keeping latest; drain idle/atspi before starting a heavy poll tick (AP-02).
3. **Shrink poll-path wall time**: logind multi-call reduction (AP-03); avoid 5s one-shot AT-SPI when agent exists (AP-04); TTL-cache `children_map` / tmux panes for enrich (AP-05).
4. **Stop latency**: check `stop` between collectors in `tick_all`; keep timeouts (AP-07).
5. **Do not add asyncio inside the daemon** without isolating Store ownership; prefer current “thread puts dict → main writes SQLite” pattern for any future MCP/NATS adapter (AP-13).
6. **Minor polish**: `AtspiTraceWriter.close()` on shutdown (AP-11); resolve dead `FocusEventGate` (AP-12).

**Positive patterns to preserve**

- Reader threads only `queue.put` / callback; **never** touch `Store` (avoids `check_same_thread` failures).
- `agent_worker` stdin uses `GLib.idle_add(handle_cmd)` so probe/quit run on the GLib thread.
- Exponential backoff on idle/AT-SPI respawn (`_IDLE_RESPAWN_*`, `_ATSPI_RESPAWN_*`) limits crash loops.
- `Store.batch()` groups multi-write ticks; WAL supports concurrent CLI readers.
- Most `subprocess.run` calls set explicit timeouts (no infinite hang on hung loginctl/tmux).
