# Security analysis — partitions P3 + P4

**Scope:** `src/roxabi_sense/report/**`, `surfaces/**`, `atspi/**`, `util/**`, `tools/**`  
**Date:** 2026-07-31  
**Threat model (sense):** local same-user workstation sensor. No remote network surface in these partitions yet (`surfaces/` is a stub; MCP/NATS not implemented). Attackers of interest: malicious window/MPRIS titles, poisoned agent session JSON under `$HOME`, mis-set config paths, log/terminal injection when printing facts.

### Summary

P3+P4 code is largely **defense-aware for local untrusted strings**: focus titles are sanitized (`sanitize_display` / `normalize_title`) before store/recap; subprocesses use **argv lists** (no `shell=True`); AT-SPI worker command surface is limited to `probe` / `quit`.  

Residual risk is concentrated in **privilege + privacy**, not classic RCE:

1. The AT-SPI agent is a **high-privilege same-user process** (full a11y bus) with **full parent env inheritance** and **no sandbox** — isolation is for system-python/`gi`, not security.
2. **Trace mode** and **recap/media** can emit sensitive titles/paths; media/meeting/agent fields lack report-layer re-sanitization.
3. **Session registry** trusts local JSON without size/schema bounds (same-user integrity).
4. **tools/** has only a fixed-argv license checker; no exfil tooling.

**No P0 findings.** Highest items are P2 (a11y privilege boundary, env inheritance, raw title firehose when trace on, config-writable trace path).

### Recommendations

1. **Minimize AT-SPI agent env** (SEC-P34-001) — highest practical hardening for a same-user daemon that already needs a11y.
2. **Sanitize before any display or trace write** — reuse `sanitize_display` in `format_day_recap`, meeting labels, media fields, and `AtspiTraceWriter` (SEC-P34-003, SEC-P34-005, SEC-P34-009).
3. **Treat opt-in AT-SPI trace as sensitive data** — default path under XDG, dir `0o700`, file `0o600`, document retention (SEC-P34-003/004).
4. **Bound session registry I/O** — max size + scalar field validation (SEC-P34-011).
5. **Keep surfaces thin when MCP/NATS arrive** — no title firehose; auth on MCP; coarse NATS only (SEC-P34-015).
6. **Do not expand tools into runtime collectors** — license_check stays CI-only with timeout (SEC-P34-016).
7. **Document a11y residual risk** next to “no OCR/keylogging” product rules so operators understand AT-SPI is intentionally powerful (SEC-P34-002).

### Positive controls observed

- No `shell=True`, `eval`, or dynamic code exec in scope.
- AT-SPI worker path fixed from package (`agent_worker.py` beside `agent.py`); stdin cmds allowlisted.
- Focus titles: C0 strip + length cap before recap dwell attribution.
- tmux binary resolved to known absolute paths; pane listing timed out.
- Trace parent directory created `0o700`.
- Session registries are **read-only** consumers of `~/.grok` / `~/.claude` (matches project hard rule).
- Report/presence modules are pure compile-over-store (no collectors, no outbound network).
