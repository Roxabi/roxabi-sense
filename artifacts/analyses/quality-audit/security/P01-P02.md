# Security Analysis — P1 + P2

**Scope:** collectors (`P1`), store + package root / daemons (`P2`)  
**Paths:** `src/roxabi_sense/collectors/**`, `store/**`, `cli.py`, `config.py`, `paths.py`, `daemon*.py`, `install_service.py`  
**Also inspected (support for P1):** `util/session_registry.py`, `util/titles.py` (agent-session JSON + title sanitization used by collectors)  
**Date:** 2026-07-31  
**Method:** OWASP-minded static review (path, injection, SQLite, untrusted input, permissions, secrets, subprocess)

### Summary

P1+P2 is a **local, single-user** attention sensor: collectors read agent/desktop state, append facts to SQLite, and expose CLI/daemon surfaces. There is **no network listener**, **no credential store**, and **no `shell=True`**. SQLite access is parameterized; process-name inputs to `pgrep` are allowlisted; window titles are stripped of C0 controls before store/display.

Residual risk is concentrated in:

1. **Untrusted local JSON** from `~/.grok` / `~/.claude` (no size caps; symlink follow on session files).
2. **Env/config-controlled paths** (`SENSE_DB`, `XDG_*`, config `db_path` / `atspi_trace_path`) with no containment.
3. **CLI/store limits** that can disable SQL `LIMIT` (`--limit -1`).
4. **Subprocess arg surfaces** that trust peer tool output (`loginctl` session id, `playerctl` player names) without shape checks (list-form argv → not shell injection, but weak hygiene).
5. **systemd unit generation** that interpolates binary paths without quoting (PATH hijack / space / control-char in unit body).

Threat model: local user compromise, malicious home-dir artifacts, or hostile config/env — not remote RCE. **No P0** found under that model.

### Findings

| ID | Severity | File:Line | Finding | Evidence | Recommendation |
|----|----------|-----------|---------|----------|----------------|
| SEC-01 | P2 | `util/session_registry.py:93–116`, `135–168`; `collectors/agent_sessions.py:40–47` | Untrusted agent JSON: full-file `read_text` + `json.loads` with **no size limit**; fields stored into SQLite snapshots | `_parse_grok_file` / `_parse_claude_dir` load entire files; `AgentSessionsCollector.tick` appends all sessions. A multi‑GB or deeply nested JSON under `~/.grok` / `~/.claude/sessions` can OOM or stall the daemon poll loop. Type checks (`isinstance`) mitigate structure bombs into typed fields, not memory. | Cap read size (e.g. 1–4 MiB/file); reject oversized dirs; bound `sessions` list length before `store.append`. |
| SEC-02 | P2 | `util/session_registry.py:124–146` | Session dir `glob("*.json")` + `read_text` **follows symlinks** | No `is_symlink()` / `resolve()` containment under `claude_dir`. A planted `~/.claude/sessions/evil.json` → sensitive path is opened if readable; only JSON-shaped keys are projected, but still enables **unauthorized file open** and partial metadata exfil into the store. Grok path is a single file path (same follow behavior via `is_file`+read). | Skip symlinks (`path.is_symlink()`); after resolve, require `resolved.is_relative_to(claude_dir.resolve())`. Treat non-regular files as missing. |
| SEC-03 | P2 | `paths.py:9–34`; `config.py:79–80`, `96–97`, `119–120`; `store/db.py:72–74` | Unvalidated path overrides for DB/config/trace: env + TOML can point store **anywhere writable** | `SENSE_DB` / `SENSE_CONFIG` / `XDG_DATA_HOME` / `XDG_CONFIG_HOME` and `[daemon] db_path` / `atspi_trace_path` become `Path(...)` with no allowlist. `Store.__init__` `mkdir(parents=True)` + creates SQLite at that path. | SEC-04 | P2 | `cli.py:54`, `197–204`; `store/db.py:188–218` | Negative `LIMIT` disables bound on event reads | CLI `--limit` is bare `type=int` (allows `-1`). SQLite treats negative LIMIT as **unbounded**. Large day histories + fat payloads (desktop windows, media) can exhaust memory on `sense day`. | `limit = max(1, min(limit, MAX))` in CLI and/or store; reject `limit < 1`. |
| SEC-05 | P2 | `install_service.py:49–59`, `34–42` | systemd unit body interpolates binary path without quoting; binary resolved via `PATH` | `ExecStart={exec_start}` with `cmd = f"{binary} daemon"`. | SEC-06 | P3 | `collectors/idle.py:77–96` | `loginctl` session id from tool stdout passed as argv without shape check | `_active_session` takes `parts[0]` from `list-sessions`; `_prop(session, name)` runs `["loginctl", "show-session", session, ...]`. `shell=False` → no shell injection; unvalidated session string is still weak trust of peer CLI. | Accept only `re.fullmatch(r"[0-9a-zA-Z_-]+", session)` (or digits-only as logind uses). |
| SEC-07 | P3 | `collectors/mpris.py:49–73` | Player names from `playerctl -l` passed to `-p` without validation | List-form argv avoids shell injection; hostile/odd MPRIS bus names could confuse `playerctl` or bloat metadata stored in snapshots. | Allowlist player names (`[A-Za-z0-9._:-]{1,128}`); drop others. |
| SEC-08 | P3 | `collectors/idle_watch.py:132–139`, `183–197` | `SENSE_IDLE_PYTHON` env can select **any executable** as idle-watch subprocess | `resolve_idle_python()` returns override if `Path(override).is_file()`. | SEC-09 | P3 | `store/db.py:89–99`; `atspi/trace_log.py:34–77` (trace via daemon) | DB files hardened to `0600` / dir `0700`; **trace JSONL and unit files are not chmod'd** | Store: `chmod` parent `0o700`, db/wal/shm `0o600` — good. | SEC-10 | P3 | `config.py:69–116` | Config TOML fully trusted; no schema bounds | `process_names` tuple length unbounded (mitigated by collector `_NAME_RE`); floats/paths accepted blindly; corrupt TOML raises to CLI. | SEC-11 | P3 | `collectors/focus_atspi.py:158–169`; `collectors/mpris.py:83–89`; `collectors/tmux_sessions.py:58–67` | Sensitive **activity facts** persisted (titles, media, paths, cwds) | Local privacy / shoulder-surfing via DB or `sense status` previews — not injection. | SEC-12 | P3 | `store/db.py:237–241` | `json.loads` on DB payload without size/type guard beyond “dict wrap” | Malicious/corrupted DB (same-user write) can inflate memory or crash CLI/daemon on read. | Catch `JSONDecodeError`; size-cap payload blobs; treat bad rows as empty `{}`. |

#### Positive controls (no finding)

| Area | Evidence |
|------|----------|
| No `shell=True` / `os.system` / `eval` | All `subprocess.run`/`Popen` use argv lists under collectors, install, idle_watch. |
| SQLite injection | All queries use `?` binds; `IN` clause builds only placeholders (`store/db.py:210–218`). |
| `pgrep` arg injection | `ProcessPresenceCollector` filters names with `_NAME_RE` and `pgrep -xi --` (`process_presence.py:13–21`, `46–47`). |
| Binary path pinning | `tmux` / `playerctl` candidates are fixed absolute paths (`tmux_sessions.py:13`, `mpris.py:13–16`). |
| Title terminal injection | `sanitize_display` strips C0/DEL and caps length (`util/titles.py:26–36`); used in focus enrich. |
| Secrets / tokens | No API keys, passwords, or auth tokens in P1+P2 surface; NATS machine name only (`config.machine`). |
| Agent history write protection | Collectors read registries only; no write to `~/.claude` / `~/.grok` histories. |

### Recommendations

**Priority order**

1. **SEC-01 + SEC-02 (agent JSON)** — Treat `~/.claude/sessions` and `~/.grok/active_sessions.json` as untrusted peer data: size caps, symlink refusal, max session count. Highest practical DoS / odd-exfil risk for the agent-session collector path.
2. **SEC-04** — Clamp CLI/store `limit` to a positive max (e.g. 1…10_000). One-line defense-in-depth against accidental or scripted unbounded reads.
3. **SEC-05** — Harden `install-service` unit generation (quoted `ExecStart`, absolute trusted binary).
4. **SEC-03** — Document env/config path trust; optional home/XDG containment for non-dev use.
5. **SEC-06–08** — Cheap allowlists on session ids, player names, idle-watch python path.
6. **SEC-09** — `chmod 0o600` on trace JSONL (and unit file) after create.
7. Keep existing strengths: no shell, parameterized SQL, `pgrep` name filter, fixed tool paths, title C0 sanitization, DB `0700`/`0600`.

**Out of scope / deferred to P3+P4 audit**

- Full AT-SPI worker (`atspi/agent_worker.py`) attack surface (desktop bus trust).
- `util/agent_link` /proc + title scoring (integrity of agent attribution, not RCE).
- Future MCP/NATS surfaces (must not leak title firehose; auth if ever remote).

**Residual acceptance**

For a **local single-user systemd --user** journal, P2 items are acceptable short-term if the home directory and env are trusted. They become material under shared-account, compromised config, or hostile files planted under agent config dirs.
