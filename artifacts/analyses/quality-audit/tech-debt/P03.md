### Summary

**Report layer is the mature query spine** (presence SM, day recap, segments, meeting annotation, enrich) and correctly positions itself as the shared entry for future MCP/NATS. **Surfaces package is empty** — only a docstring promising MCP/NATS. Report debt is mostly **magic display/limit constants**, **duplicated `parse_ts`**, **idle gap not config-driven**, and **tolerance for dead `media` kind**. No TODO markers. Highest severity: **surfaces vacancy** (P1 product roadmap) and **config-unaware recap thresholds** (P2 behavioral drift).

### Recommendations

1. **Treat empty `surfaces/` as phase-3 epic** — do not grow query logic in CLI; keep report as SSOT (already good).
2. **Wire idle gap/threshold from config into recap** so operator idle settings and away segments stay coherent.
3. **Centralize `parse_ts` / duration helpers** before more report modules appear.
4. **Add truncation honesty** on day event limit for large DBs.
5. **MCP redaction as adapter-only** when implementing — prevent report from growing surface-specific branches (axial).
